# curatomatic

Semi-automated curation of GTDB reference trees for new releases.

_This tool was developed for internal use, it is not supported for public use._

- The taxonomy file comes from gDecorate (this is the `decorate_classifications.tsv` file`)

- The metadata file is the GTDB metadata file and must have the `ncbi_wgs_formatted` column (configurable) to do novel taxon creation.
- The red distribution comes from gDecorate from the median red rank distribution

## Installation

A static Linux binary (`x86_64-unknown-linux-musl`, no glibc needed) is attached to every
[release](https://github.com/Ecogenomics/curatomatic/releases). Download the `.tar.gz` and its `.sha256`, check it,
and unpack it (replace `VERSION`, e.g. `1.0.0`):

```shell
sha256sum -c curatomatic-vVERSION-x86_64-unknown-linux-musl.tar.gz.sha256
tar xzf curatomatic-vVERSION-x86_64-unknown-linux-musl.tar.gz
./curatomatic-vVERSION-x86_64-unknown-linux-musl/curatomatic --version
```

The changes in each version are in [CHANGELOG.md](CHANGELOG.md). On any other platform, build it from source.

## Building

```shell
git clone https://github.com/Ecogenomics/curatomatic.git
cd curatomatic
cargo build --release
```

The binary is written to `./target/release/curatomatic`.

## Running

```shell
./target/release/curatomatic [OPTIONS] --taxonomy <PATH> <TREE> <MEDIAN_RED> <OUT_DIR>
```

The following arguments are required:

- `TREE` = Path to the RED decorated and scaled tree (generated by Phylorank).
    - e.g. `gtdb_r232_bac120.decorated.red_decorated.tree`
- `MEDIAN_RED` = Path to the median RED of each rank, see [Median RED file](#median-red-file-median_red).
- `OUT_DIR` = Output directory to write to. It must not already exist (unless `--log debug` is given).

The following options are available:

- `--log [debug|info|warning|error|critical]` = Output logging messages equal, or above this level (default = info).
- `--min-bs FLOAT` = Minimum bootstrap value to consider for decoration (default = 95).
- `--taxonomy PATH` = **Required.** The taxonomy of each genome (see [Taxonomy file](#taxonomy-file---taxonomy)). It names the ranks the tree can't hold, and gives every leaf its species.
- `--prior-taxonomy PATH` = The taxonomy of each genome in a previous release, in the format of the [taxonomy file](#taxonomy-file---taxonomy). It is the prior taxonomy for downward refinement and the report: without it no taxon is moved down. Genomes that are not on the tree are ignored, and a genome on the tree that is not in the file has no prior. It can't be `--taxonomy`: that is the decoration of the same tree, so every genome below a taxon has it, and a taxon could never move down. A previous release classifies every genome fully, so each row (including genomes not on the tree) must be exactly seven named taxa, one per rank, and a binomial species in the row's genus; anything else stops the run (see [Taxonomy file](#taxonomy-file---taxonomy)).
- `--novel-name-file PATH` = File giving the name used for novel taxa of each genome (see [Novel name file](#novel-name-file---novel-name-file)). Requires `--novel-name-column`.
- `--novel-accession NAME` = The column of `--novel-name-file` that holds the genome IDs, e.g. `db_name` (default = `accession`). Requires `--novel-name-file`.
- `--novel-name-column NAME` = The column of `--novel-name-file` that holds the names, e.g. `ncbi_wgs_formatted`. Requires `--novel-name-file`.
- `--debug` = Also write the inputs as curatomatic loaded them, before any curation (see [Output](#output)).
- `-h, --help` = Print the help.
- `-V, --version` = Print the version.

### Median RED file (`MEDIAN_RED`)

A tab separated file with a header and one row per rank, giving the median RED of that rank, e.g.
`gtdb_r237_median_red_rank_distribution.tsv` (see `example/gtdb_r226_ar53.median_red_rank_distribution.tsv`):

```
rank	median
Phylum	0.23103292252099542
...
Genus	0.9068450718741943
```

- The `rank` and `median` columns are found by name. Any other column (e.g. `mean`, `p95`) is ignored.
- A rank is its full name, in any case (`Phylum`, `phylum`).
- The domain is always `0.0` and the species always `1.0`. They need no row; a row for either must have that value.
- A missing column, a median that is not a number, an unknown rank, or a rank given twice is an error.

### Taxonomy file (`--taxonomy`)

A tab separated file with no header and two columns, the genome ID and its taxonomy string, e.g. the
`decorate_classifications.tsv` of gDecorate (see `example/gtdb_r237_decorated_taxonomy.tsv`):

```
G003697165	d__Bacteria;p__Pseudomonadota;c__Gammaproteobacteria;o__Enterobacterales;f__Enterobacteriaceae;g__Escherichia;s__Escherichia coli
```

- Each taxon is a rank prefix (`d`, `p`, `c`, `o`, `f`, `g` or `s`), then `__`, then its name: `g__Escherichia`,
  `s__Escherichia coli`, `g__Luteimonas_D`, `g__CAG-698`, `s__{unresolved} sp1`. The name must not start with `_` or
  whitespace, and must not end with whitespace (`gFoo`, `g_Foo`, `g___Foo` and `g__ Foo` are errors). Spaces around a
  `;` are ignored. The same format applies to the taxa in the tree's labels and in `--prior-taxonomy`; a malformed
  taxon stops the run.
- A bare prefix (`g__`) is a placeholder, not a name. Placeholders are stripped from each row as it is read, so
  `d__Bacteria;p__;c__;o__;f__;g__;s__Escherichia coli` holds only the domain and species. A rank that holds both a
  placeholder and a name (`g__;g__Escherichia`) is an error. A placeholder in `--prior-taxonomy` is an error (see
  below). A placeholder in a label of the tree (e.g. `100:g__|RED=0.9`) is an error that stops the run.
- Each row must be in rank order (domain first, species last), give each taxon once, and have at most one domain and
  one species. A row that does not is an error that stops the run, in both `--taxonomy` and `--prior-taxonomy`. A rank
  other than the domain and species can hold several taxa (nested taxa, e.g. `g__JAAYFO01;g__Neosphaerochaeta`).
- `--prior-taxonomy` is stricter: every row must be exactly seven taxa, `d__` to `s__` in order, each with a name, and
  the species must be a binomial name (two words separated by one space) whose first word is the row's genus
  (`g__Escherichia;s__Escherichia coli`, `g__CAG-698;s__CAG-698 sp000123`). A placeholder, a missing rank, two taxa of
  a rank, an unresolved species (`s__{unresolved} sp1`) or a species of another genus stops the run, naming the line.
- Genome IDs are matched to the tree the same way as the novel name file (`GB_GCA_003697165.1` is `G003697165`).
- The file holds what the dummy nodes of the old trees held. Each row is the full taxonomy of the genome: the taxa on
  its path in the tree, plus its own. Each leaf is given every named taxon of its row that is **not on its path** in
  the tree. This is matched by taxon, not by rank: in
  `...;f__Sphaerochaetaceae;g__JAAYFO01;g__Neosphaerochaeta;s__Neosphaerochaeta fermentans`, where the tree has
  `g__JAAYFO01` above the genome, the leaf gets `g__Neosphaerochaeta` and its species. The taxa already on the tree are
  never changed.
- Once the file is assigned, the named taxa on each genome's path and leaf must be exactly the taxa of its row,
  matched by taxon in any order. A taxon on the tree that is not in the row (the tree puts the genome in `p__A` and
  its row says `p__B`, or its row has `f__` where the tree has `f__F`) means the tree and the file disagree, and the
  run fails naming the genome and the taxa.
- A species such as `s__{unresolved} sp053939565` is a name, and is kept exactly as read.
- A taxon to assign that is already elsewhere on the tree, or that more than one leaf would get, is an error.
- Every leaf must hold its own named species once the file is assigned: a row whose species is a placeholder
  (`s__`, stripped, so the row has no species), or a species on an internal node of the tree, is an error. This is checked again at the end of the run,
  before any output is written.
- Every genome must have a named domain, on the tree above it or in its row: a genome with neither (`d__` in its row
  and no domain on the tree) is an error, checked at the same two points as the species.
- A genome on the tree that is not in the file is an error. A genome in the file that is not on the tree is a warning.
- A line without two columns, an invalid taxonomy, or a genome given twice is an error.

### Novel name file (`--novel-name-file`)

A tab separated file with a header, giving the name (e.g. the NCBI WGS prefix) used for each genome when a novel
taxon is created. The GTDB metadata file can be used as is, e.g. `gtdb_r237_bac120_metadata.tsv` with
`--novel-name-column ncbi_wgs_formatted` (see `example/meta.tsv`):

```
accession	ncbi_wgs_formatted
GB_GCA_123456789.1	FOO
```

- Only the genome ID column (named by `--novel-accession`, `accession` by default) and the column named by
  `--novel-name-column` are read, both found by header name. Any other column is ignored. A file whose genome IDs are
  in another column, e.g. `example/gtdb_r237_bac120_metadata_slim.tsv` (`db_name`), is read with
  `--novel-accession db_name`.
- Genome IDs are trimmed and matched to the tree in their canonical form (`GB_GCA_000008885.1` is `G000008885`).
- A value of `none`, `n/a`, `null` or empty (after trimming, in any case) means the genome has no name.
- A missing genome ID or name column, or a row too short to hold either, is an error.
- Genomes without a name are given novel taxa named after their genome ID. If every name a novel taxon could have is
  already taken, it is unresolvable: it is not created (its genomes keep the placeholder of the rank, e.g. `g__`), and
  it is only a row of the report, `<rank>__UNRESOLVABLE` with action `unresolvable`, for a curator to name (see
  [docs/refinement.md](docs/refinement.md), "Novel taxa").

## Output

The following files are written to `OUT_DIR`:

- `<tree stem>.curatomatic.tree` = The curated tree, where `<tree stem>` is the file name of `TREE` without its last extension (e.g. `gtdb_r226_ar53.decorated.scaled.red.curatomatic.tree`). Leaf labels are written exactly as they were read (the genome ID): the taxa a leaf holds are only in the taxonomy and leaf taxonomy files below.
- `<tree stem>.curatomatic.report.tsv` = One row per taxon that curatomatic moved or created, and one per novel taxon it could not name, with flags for the changes to review (see below).
- `<tree stem>.curatomatic.taxonomy.tsv` = The curated taxonomy of each genome, in the format of the [taxonomy file](#taxonomy-file---taxonomy), one row per genome in tree order. Each rank is the taxon nearest the leaf on its path in the curated tree. A rank with no named taxon is written as a placeholder (`p__`), so every row has all 7 ranks: this happens when a novel taxon was not created because a valid name of a lower rank is below it (see [docs/refinement.md](docs/refinement.md), "Novel taxa"), and the rank is left for a curator to fill.
- `<tree stem>.curatomatic.leaf-taxonomy.tsv` = The taxa held by each leaf, which the Newick tree can't hold, one row per genome in tree order (see below).
- `curatomatic.log` = The log of the run.

The report has a header row and these columns (several values in one column are joined by `,`):

- `taxon`, `rank` = The taxon, and its rank prefix (`g`). An unresolvable novel taxon is `<rank>__UNRESOLVABLE`.
- `action` = `moved_up`, `moved_down`, `novel` (created), or `unresolvable` (a novel taxon that was not created,
  because every name it could have is already a taxon).
- `flag` = The flags to review: `nested_in_same_rank`, `novel_low_red`, `sister_join_past_child_thresh`,
  `unsupported_label`, `large_gain`, `displaced_from_prior`, `new_in_decoration`, and `namesake_outside_taxon` (an
  unresolvable taxon, whose namesakes are elsewhere on the tree).
- `n_genomes_before`, `n_genomes_after`, `bootstrap_before`, `bootstrap_after`, `red_before`, `red_after` = The node
  of the taxon on the input tree (empty for a novel or unresolvable taxon), and on the curated tree. For an
  unresolvable taxon, `*_after` is the node it would have been placed on.
- `prior_taxon` = The taxa of this rank that the genomes of a novel taxon had in `--prior-taxonomy`.
- `nested_in`, `sister_taxa` = The closest taxon of the same rank it is nested in, and the closest that join it past
  the child threshold.
- `namesakes` = For an unresolvable taxon, the taxa named after its genomes that refused each name (e.g.
  `g__G020350785`), which also say which genomes it is.

The leaf taxonomy file has no header and two columns, the genome ID (as the leaf is labelled) and the taxa that the
leaf itself holds, joined by `;`:

```
G003697165	s__Escherichia coli
G053840885	g__Neosphaerochaeta;s__Neosphaerochaeta fermentans
```

- A row holds only the leaf's own taxa, in rank order: the taxa its row of `--taxonomy` gave it that are not on its
  path in the tree (e.g. a single genome genus inside a genus on the tree), plus any taxon that curation moved down
  onto it or created on it. It never holds a taxon of the leaf's path, and has **no placeholders**, unlike
  `<tree stem>.curatomatic.taxonomy.tsv`.
- Every leaf holds its species, so every genome has a row, and most rows are the species alone.
- Several taxa of one rank are all written, in the order the leaf holds them (that of its `--taxonomy` row for the taxa
  the row gave it).
- To rebuild the full taxonomy of a genome, every nested taxon included: take the named taxa of the internal nodes on
  its path in the curated tree, then add its row of this file, and order them by rank (keeping the path order, root
  first, within a rank, and the leaf's taxa last). Together, the tree and this file hold every taxon that curatomatic
  holds.
- It can be read as a [taxonomy file](#taxonomy-file---taxonomy), but it is not a valid `--taxonomy` for the curated
  tree, as each `--taxonomy` row must be the genome's full taxonomy.

With `--debug`, the inputs as they were loaded (before any curation) are also written:

- `<tree stem>.debug.zombie.tree` = The tree with a dummy node above each leaf, as in the old trees: leaf `G` is written
  as `('G|RED=1.0':0.0,'D-G|RED=1.0':0.0)'<the leaf's taxa>|RED=1.0':<its branch length>`.
- `<tree stem>.debug.taxonomy.tsv` = The full taxonomy of each genome, every nested taxon included, in the format of
  the [taxonomy file](#taxonomy-file---taxonomy).

These check that nothing is lost when the inputs are loaded. For an old style tree with dummy nodes:

```shell
python scripts/convert_python_inputs.py test_data/python/input /tmp/converted   # remove the dummy nodes
./target/release/curatomatic --debug --taxonomy /tmp/converted/r226_ar53.taxonomy.tsv \
    /tmp/converted/r226_ar53.decorated.scaled.red.tree /tmp/converted/r226_ar53.median_red.tsv /tmp/output
python scripts/check_round_trip.py test_data/python/input/r226_ar53.decorated.scaled.red.tree \
    /tmp/output/r226_ar53.decorated.scaled.red.debug.zombie.tree \
    /tmp/converted/r226_ar53.taxonomy.tsv /tmp/output/r226_ar53.decorated.scaled.red.debug.taxonomy.tsv
```

The zombie tree must match the original node for node, and the taxonomy must match the input file.
