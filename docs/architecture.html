Inside Curatomatic

Curatomatic reads a decorated tree, moves the existing taxon labels to better nodes, and creates novel taxa where genomes are missing a rank. It never changes the tree itself. This page shows how it does that: the pipeline, the data structures and the rules, as read from the code.

Overview

What goes in, what comes out

Inputs

  • Tree: Newick, internal nodes labelled bootstrap:taxa|RED=x, leaves labelled with their genome ID.
  • Median RED: TSV with the median RED of each rank.
  • --taxonomy (required): the full taxonomy of every genome. Gives the leaves the taxa the tree can't hold.
  • --prior-taxonomy: the previous release. Needed to move taxa down.
  • --novel-name-file: WGS names for novel taxa.

What it does

  • Moves each phylum, class, order, family and genus label to the best node nearby, judged by RED and bootstrap.
  • Creates a novel taxon for each rank a genome is missing, where no named taxon below would be covered.
  • Checks, before writing anything, that taxa were only moved or created.

Outputs

  • <stem>.curatomatic.tree: same structure, new label positions, RED removed.
  • <stem>.curatomatic.taxonomy.tsv: one row per genome.
  • <stem>.curatomatic.report.tsv: one row per moved or novel taxon, with flags to review.
  • curatomatic.log, and with --debug the inputs as loaded.

The rules that hold everywhere

  1. 1The tree structure, branch lengths, bootstraps and RED values are never changed. Only the taxon labels move. RED is stripped from the internal labels only when the tree is written.
  2. 2A taxon is only ever moved or created. It is never removed, copied or renamed. Placeholders such as g__ are not names and are exempt.
  3. 3The inputs are taken as given. Anything in the tree or --taxonomy that doesn't line up is an error, never a silent skip.
  4. 4A leaf label is always its genome ID. The taxa a leaf holds live on its Leaf and go to the taxonomy file only.
  5. 5Every leaf holds its own named species, checked after loading and again before output.

    Data structures

    How the tree is held in memory

    The Newick tree is an arena of nodes numbered in post-order, so a NodeId is also an index into every per-node vector. Tree wraps it with the parsed labels and the leaves' taxa.

    Where a node's taxa live

    • Internal node: in its Newick label. Moving a taxon rewrites the label through NewickTree::set_internal_label.
    • Leaf: on its Leaf.taxonomy. The label stays the genome ID, and set_internal_label refuses a leaf.
    • node_labels merges both views, and is only current after Tree::reload, which also rebuilds taxon_labels and checks that each taxon is on one node.

    Newtypes

    • GenomeId: canonical, GB_GCA_003697165.1 → G003697165.
    • Taxon: the name with its prefix. g__ is a placeholder, not a name (is_named needs more than 3 characters).
    • RedValue, BootstrapValue: wrapped f64. A leaf is RED 1.0, and counts as bootstrap 100 when moves are ranked.
    • Rank: Domain → Species. Its order is the rank order, so “higher rank” means a smaller value.

    RED windows · src/red.rs, src/tree.rs

    Where each rank belongs

    Each rank has a median RED. Its window runs from the midpoint with its parent rank (towards the root) to the midpoint with its child rank (towards the leaves). The domain is fixed at 0.0 and the species at 1.0. Moving a taxon up only considers ancestors inside the window, and a novel taxon is only placed at or below the top of the window.

    RankMedianWindow (upper – lower)RED deltaThis node for the rank

    “Upper” is the bound nearer the root (the smaller RED). Moving up stops at the first ancestor above the window, and skips ancestors below it. A novel taxon of a rank needs RED ≥ the upper bound (halfway_to, which equals the midpoint except perhaps in the last bit).

    Leaf taxa · Tree::assign_leaf_taxonomy

    Giving the leaves what the tree can't hold

    The tree has nowhere to put the taxa of a single genome (its species, or a one-genome genus). Each row of --taxonomy is a genome's full taxonomy, and the leaf gets every named taxon in the row that is not already on its path. This is matched by taxon, never by position or rank.

    flowchart TD
    L["Each leaf, genome G"] --> R{"G in --taxonomy?"}
    R -- no --> E1["Error: MissingFromTaxonomyFile"]
    R -- yes --> U["Walk up and collect the named taxa on the path. The first node with a named taxon is the anchor."]
    U --> A{"Every anchor taxon in the row of G?"}
    A -- no --> E2["Error: TaxonomyFileConflict"]
    A -- yes --> D["The leaf gets every named taxon of the row that is not on the path"]
    D --> X{"Taxon already on the tree, or wanted by another leaf?"}
    X -- yes --> E3["Error: TaxonomyFileConflict"]
    X -- no --> P["Add it to Leaf.taxonomy"]

    Example: r237 G053840885

    The row has two genera. The tree already holds g__JAAYFO01 above the genome, so the leaf gets the nested genus and the species.

    ↑d__Bacteria … f__Sphaerochaetaceae (on the path)
    ↑g__JAAYFO01 (on the path, the anchor)
    ＋g__Neosphaerochaeta → leaf
    ＋s__Neosphaerochaeta fermentans → leaf

    Removing the dummy nodes of an old tree and assigning the file must give back exactly the taxa they held. This is tested by removing_the_dummy_nodes_and_assigning_the_file_restores_their_taxa.

    Refinement · Tree::refine_existing_labels, Tree::process_refinement

    Moving labels to better nodes

    One pass per rank, from phylum down to genus. Each pass finds all candidate nodes for every taxon of the rank on the tree as it is at the start of the pass, moves each taxon to its best candidate, then reloads the tree so the next rank sees the moves.

    flowchart TD
    S["Pass for rank R: phylum, class, order, family, then genus"] --> W["Window of R from the median RED"]
    W --> N["Every node in post-order with a taxonomy and a bootstrap"]
    N --> T["Every taxon of rank R on it"]
    T --> U["Up candidates"]
    T --> D["Down candidates"]
    U --> F["Refinement: the candidates of each taxon, in the order found"]
    D --> F
    F --> P["process_refinement: move each taxon to its best node"]
    P --> RL["Tree::reload, then the next rank"]

    Moving down

    flowchart TD
    S(["Taxon of rank R on its original node"]) --> D1{"D1: original supported and RED below the window?"}
    D1 -- yes --> NO(["No down candidates"])
    D1 -- no --> CT["D2: the taxa of R that the prior taxonomy gives the genomes under each child. Genus only: a new genome adds the Latin genus of its species, if the original node is inside the window."]
    CT --> K{"How many children contain the taxon?"}
    K -- "none, or more than one" --> STOP(["Stop"])
    K -- "exactly one" --> V["Visit that child"]
    V --> KIND{"D3: what is the child?"}
    KIND -- "a leaf" --> RL(["Record, stop"])
    KIND -- "supported" --> RS["Record"]
    RS --> FAR{"RED delta larger than the original?"}
    FAR -- yes --> STOP
    FAR -- no --> CT
    KIND -- "unsupported, higher bootstrap than the original" --> RU["Record"] --> CT

    Moving down follows the genomes that --prior-taxonomy puts in the taxon. Without it no child ever contains the taxon, so nothing moves down. It is never read from --taxonomy, because that file decorates this same tree and every genome under a taxon would have it.

    B -- yes --> K(["No move"])
    B -- no --> M["transfer_taxon: remove from the original, add to the best"]

      Filling in missing ranks

      After refinement, every leaf whose path is missing a rank gets a novel taxon for that rank, placed as high as the tree allows. Leaves that reach the same node share one taxon. A novel taxon is never placed above a valid name of a lower rank, because a curator never would.

      flowchart TD
    M["Tree::get_leaf_nodes_missing_rank: leaves whose path lacks a rank"] --> E["Each leaf and missing rank R, from phylum down"]
    E --> W["Walk up from the leaf, the leaf included"]
    W --> A{"A node below holds a taxon of R?"}
    A -- yes --> H["Take the highest candidate. None is NoCandidateNode."]
    A -- no --> OK{"No bootstrap or supported, and RED at least halfway from the parent median to the R median?"}
    OK -- yes --> C["Candidate"] --> W
    OK -- no --> W
    H --> G["Leaves with the same highest node share one taxon"]
    G --> V{"A valid name of a rank lower than R, species excluded, at or below the node?"}
    V -- yes --> SK["Skip: the leaves keep the placeholder of R"]
    V -- no --> NM["generate_unique_rank: the most readable WGS name, else the lowest unused genome ID, else R__UNRESOLVABLE"]
    NM --> P["Add the novel taxon to the node"]

      Naming, in order of preference

      • The WGS names of the genomes under the node, from --novel-name-file, that are not already taxa on the tree. Names without a confusable pair (I/l, 0/O, 1/I, 5/S, 2/Z) win, then the alphabetically lowest. For example g__JAAYFO01.
      • The lowest genome ID whose name is not taken. For example g__G963674675.
      • <rank>__UNRESOLVABLE, the only taxon allowed on more than one node, for a curator to name.

      Details from the code

      • The candidates and the valid names below each node are read before any novel taxon is created.
      • Ranks are created from phylum down to genus.
      • A valid name is any named taxon except an unresolved species (s__{unresolved} …). Species never count, or every genome would block every novel genus.
      • A missing domain has no parent rank to bound its RED, and is a NoParentRank error.
      • The leaf itself (no bootstrap, RED 1.0) is always a candidate, so a leaf with no other candidate gets the taxon on itself.

      What a curator reviews

      One row per taxon that was moved or created, sorted by rank then taxon. A taxon that was left where it was has no row. The action is moved_up when the new node is an ancestor of the old one, otherwise moved_down, or novel. Flags are only set for phylum to genus.

      FlagSet when
      nested_in_same_rankAnother named taxon of the same rank is on an ancestor (named in nested_in).
      novel_low_redA novel taxon with 2 or more genomes on a node with q < 0.5, where q is 0 at the upper window bound and 1 at the median.
      sister_join_past_child_threshThe closest sister taxa of the same rank join it below the lower window bound (named in sister_taxa).
      unsupported_labelThe node now holding the taxon has a bootstrap below --min-bs.
      large_gainA move that multiplied the number of genomes by 5 or more.
      displaced_from_priorA novel taxon whose genomes had a taxon of this rank in the prior taxonomy (named in prior_taxon).
      new_in_decorationA moved taxon that is not in the prior taxonomy (only when --prior-taxonomy is given).

      Columns: taxon, rank, action, flag, n_genomes_before, n_genomes_after, bootstrap_before, bootstrap_after, red_before, red_after, prior_taxon, nested_in, sister_taxa.
